CHIMERA

Privacy Policy

Effective 29 August 2026 Version 1.0

CHIMERA is a local-first video editing and measurement tool. It runs entirely on its owner's own computer. It has no server, no user accounts, no analytics and no third-party data sharing. This document states exactly which TikTok data it reads, where that data is kept, and how to remove it.

01

Who this policy covers

CHIMERA is single-user software. The only person whose data it ever touches is the person who installed it and authorised their own TikTok account. There is no other class of user, no visitor, and no customer.

CHIMERA is not offered as a hosted service. There is nothing to sign up for. Anyone running it holds their own copy on their own machine.

02

What data is read from TikTok

CHIMERA requests three read-only permissions. It requests no write permission of any kind — it cannot post, delete, edit or comment.

Permission What is read Why
user.info.basic Account identifier and display name To confirm which account the stored token belongs to, so measurements are never attributed to the wrong channel
user.info.stats Follower count and total video count Reach is only interpretable relative to audience size; these provide the denominator for the analysis
video.list The owner's own published videos: identifier, title, duration, and public view, like, comment and share counts The measured outcome each video is compared against

No other person's data is ever requested or received. CHIMERA has no access to direct messages, to private videos, to other accounts, to the owner's contacts, or to any advertising or commercial data.

03

Where that data is kept

Everything stays on the owner's own machine. Two locations, both local:

  • Access credentials. The OAuth access token and refresh token are written to ~/.chimera/tiktok.json. This file never leaves the machine.
  • Measurements. Video metrics and the measurements taken from the corresponding local video files are written to ordinary project files in the owner's own working directory.
No transmission

CHIMERA sends data to exactly one destination: TikTok's own API endpoints, in order to fulfil the requests above. It contacts no other network service. There is no telemetry, no crash reporting, no usage analytics, and no backend belonging to CHIMERA at all.

04

How authorisation works

CHIMERA never sees, handles or stores a TikTok password. Authorisation uses the OAuth 2.0 Authorization Code flow with PKCE (RFC 7636). The login itself happens on TikTok's own domain, in the owner's own browser.

The application's client secret is supplied by the owner at the moment of authorisation and is deliberately never accepted as a command-line argument, so that it cannot end up in shell history or process lists.

05

Retention and deletion

There is no retention schedule because there is no operator holding the data. The owner holds it and removes it directly:

  • Delete ~/.chimera/tiktok.json to remove all stored credentials. CHIMERA then has no access at all until the owner authorises again.
  • Delete the local project files to remove all stored measurements.
  • Revoke the application under TikTok's own account settings to invalidate the tokens on TikTok's side.
06

Children

CHIMERA is developer tooling and is not directed at children. It collects no data from anyone other than the person who installed it and authorised their own account.

07

Changes to this policy

If the set of permissions CHIMERA requests ever changes, this document is updated before the change takes effect, and the version number and effective date above are raised.

08
